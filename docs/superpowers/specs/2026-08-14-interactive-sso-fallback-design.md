# 交互式 SSO 登录降级设计

## 背景

`ahs-zentao` 当前通过 Playwright 无头 Chrome 使用 `ahs-zentao init` 保存的账号密码完成 CAS 登录。自动登录失败时，浏览器会被关闭，错误直接交给 MCP 客户端。上层 AI 可能因此错误地要求用户“接管浏览器”，但无头浏览器没有可见窗口，代码也没有保留或移交浏览器会话的能力。

此外，当前登录页判断硬编码了 `sso.aihuishou.com/cas/login`，没有使用已经配置的 `CAS_URL`。CAS 域名、路径或页面结构变化时，自动填写凭据的分支可能完全不执行。

## 目标

- 正常情况下继续使用无头 Chrome 和已配置凭据自动登录。
- 自动认证未完成且已经到达可交互页面时，在用户桌面打开可见 Chrome，让用户处理验证码、二次验证、密码异常或页面变化。
- 用户回复“继续”后，由一个独立 MCP 工具验证登录、保存 session 并关闭窗口。
- 向上层 AI 返回明确、稳定的等待登录状态，避免生成不存在的“浏览器控制权转交”描述。
- 交互登录窗口最多保留 10 分钟，并保证进程退出时被清理。
- 使用 `CAS_URL` 识别登录页面，不再硬编码公司域名。

## 非目标

- 不在 MCP 内保存并自动重放登录失败前的 Bug 查询或写入操作。
- 不支持在已经启动的无头浏览器进程上动态切换可见模式；Playwright 不支持这种切换。
- 不在无桌面环境、远程服务器或容器中提供虚拟桌面。
- 不绕过验证码、MFA 或其他 SSO 安全措施。

## 总体架构

新增一个进程级 `InteractiveLoginManager`，负责可见浏览器的生命周期和交互登录状态。它持有至多一个 `Browser`、`BrowserContext`、`Page`、超时定时器和初始自动登录错误。

认证流程分成两阶段：

1. `casLogin` 首先启动 `headless: true` 的 Chrome，使用配置账号密码自动登录。
2. 自动登录失败且当前机器能够启动浏览器时，先完整关闭无头浏览器，再由 `InteractiveLoginManager` 启动 `headless: false` 的新 Chrome。
3. 可见浏览器导航到禅道入口，由 SSO 重定向到登录页。代码使用配置凭据自动填写和提交；若仍停留在登录流程，窗口交由用户继续处理。
4. 当前 MCP 工具调用返回结构化的等待登录结果，不继续执行原业务操作。
5. 用户回复“继续”后，上层 AI 调用新工具 `zentao_finish_login`。
6. `zentao_finish_login` 从保留的浏览器上下文读取 `zentaosid`，通过 `/my/` 验证认证状态。成功后保存 session 并关闭浏览器；失败时保留窗口供用户继续操作。
7. 登录成功后，上层 AI 重新调用用户原先请求的 Bug 工具。

## 状态模型

交互登录管理器包含以下状态：

- `idle`：没有可见登录会话。
- `starting`：正在启动可见 Chrome，防止并发请求重复创建窗口。
- `waiting`：窗口已打开，等待用户完成登录。
- `verifying`：`zentao_finish_login` 正在检查 cookie 和认证状态。
- `expired`：10 分钟超时，资源已清理；随后立即回到 `idle`。

同一时间只允许一个交互登录会话。处于 `starting`、`waiting` 或 `verifying` 时，其他需要认证的禅道工具不会创建新窗口，而是返回相同的等待提示。

管理器需要串行化启动、完成和清理操作，避免并发工具调用同时关闭或读取同一个浏览器上下文。

## MCP 工具与返回协议

新增无参数工具：

```text
zentao_finish_login
```

工具描述必须明确告诉上层 AI：当用户表示已经在可见 Chrome 中完成登录或回复“继续”时调用该工具。

自动登录失败并成功打开可见窗口后，业务工具返回普通 MCP 文本结果，而不是未经说明的 Playwright 异常。返回内容包含稳定状态标识，例如：

```text
[INTERACTIVE_LOGIN_REQUIRED]
自动登录未完成，已打开可见的 SSO 登录窗口。
请在窗口中完成登录，然后回复“继续”。
```

这表示原业务操作尚未执行。上层 AI 不得声称已读取或修改 Bug。

`zentao_finish_login` 的结果分为：

- 成功：session 已保存、窗口已关闭，并提示上层 AI 重新调用原业务工具。
- 尚未完成：没有有效 `zentaosid`，或验证仍跳转到 CAS；窗口保持打开。
- 已超时/不存在：窗口已被清理，提示重新调用原业务工具以发起新的登录。
- 环境错误：浏览器已异常退出或上下文不可访问；清理残余资源后返回明确错误。

## 登录页识别与自动填写

登录页识别基于 `config.casUrl`：比较当前 URL 与配置 URL 的 origin 和规范化 pathname，同时允许 CAS 在 query string 中附加 `service` 等参数。不得再依赖固定公司域名。

可见降级阶段仍会尝试使用 `ZENTAO_USER` 和 `ZENTAO_PASSWORD` 自动填写并提交，以便用户通常只需处理验证码或 MFA。如果用户名、密码选择器不存在或提交失败，不关闭可见窗口；用户可以直接在页面中完成操作。

密码、cookie 和完整表单内容不得进入 MCP 返回值或普通日志。调试日志只记录阶段、URL 的 origin/path、错误类型和状态转换。

## Session 验证

完成登录不能只以存在 `zentaosid` 为成功标准。必须携带该 cookie 请求 `${ZENTAO_URL}/my/`，并确认响应没有再次跳转到 CAS。

验证成功后按现有格式保存 `zentaosid`，并将 `expiresAt` 设置为当前时间之后 24 小时：

```json
{
  "zentaosid": "...",
  "expiresAt": 1780000000000
}
```

`expiresAt` 继续使用当前 24 小时 TTL。验证或保存成功后才关闭可见浏览器。

## 生命周期与清理

- 可见窗口启动后设置 10 分钟超时。
- 超时时关闭 page、context 和 browser，取消定时器并回到 `idle`。
- 成功完成登录时取消超时并关闭浏览器。
- 浏览器被用户手动关闭时清理内部状态；下一次完成调用返回“会话不存在”。
- MCP 进程收到正常退出信号时尽力关闭活动浏览器。
- 新交互会话启动前清理任何失效的旧句柄。

## 无法显示浏览器的环境

只有在本地桌面环境中，`headless: false` 才能向用户显示窗口。如果 Chrome 未安装、浏览器无法启动或系统没有图形显示环境，返回真实的环境错误以及排查建议。不得返回“已打开登录窗口”。

无头阶段的网络错误、DNS 错误和禅道不可达也应直接报告；启动可见窗口不能修复这些问题。交互降级主要用于已经到达 SSO 页面但自动认证未完成的场景。

## 代码边界

- `src/auth/cas-login.ts`：保留无头自动登录职责，并使用配置的 CAS URL。
- 新的交互登录模块：封装状态机、可见浏览器生命周期、完成验证和超时清理。
- 统一认证包装器：捕获“等待交互登录”状态，并为所有受保护 MCP 工具生成一致响应。
- `src/index.ts`：注册 `zentao_finish_login`，并让现有工具通过统一认证包装器执行。

Playwright 启动器、时钟和 session 验证器应通过窄接口注入交互登录管理器，使状态逻辑可以在不启动真实 Chrome 的情况下测试。

## 测试策略

自动化测试覆盖：

- 无头登录成功时不启动可见浏览器。
- 无头登录失败且可以交互处理时只启动一个可见浏览器。
- 并发或重复业务请求不会创建多个窗口。
- `zentao_finish_login` 取得并验证有效 cookie 后保存 session、取消超时并关闭浏览器。
- 没有 cookie 或验证仍跳转 CAS 时保留窗口。
- 10 分钟超时关闭所有浏览器资源并清空状态。
- 用户手动关闭窗口后的完成调用返回会话不存在。
- `CAS_URL` 的 origin/path 匹配生效，query string 不影响识别。
- 密码、cookie 不出现在返回值和日志中。
- 浏览器启动失败时不返回“窗口已打开”。
- 原有无头自动登录、Bug 查询、图片读取、解决 Bug 和添加备注的构建行为不回退。

发布前执行完整测试、TypeScript 构建和 `npm pack --dry-run`。

## 验收标准

1. 已配置账号密码且自动登录成功时，用户看不到浏览器，原工具正常执行。
2. 自动认证未完成且本机有桌面环境时，用户能看到一个 Chrome 登录窗口。
3. 第一次工具调用明确说明原业务操作尚未执行，并要求用户完成登录后回复“继续”。
4. 用户回复后，上层 AI 能正确调用 `zentao_finish_login`。
5. 完成工具验证成功后保存 session、关闭窗口，并允许原业务工具重试成功。
6. 未完成登录时窗口不被错误关闭；10 分钟后一定清理。
7. 任意时刻最多存在一个交互登录窗口。
8. 无显示环境或浏览器启动失败时返回真实错误，不声称已转交浏览器。
